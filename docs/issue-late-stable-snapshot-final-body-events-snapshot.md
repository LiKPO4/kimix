耗时投影另有独立问题：`renderTurnBody` 用当前轮所有非 user 事件的最大 timestamp 作为结束时间。由于最新用户边界缺失，1.4.486 的状态事件被归进 1.4.485 轮；最后一条为 `1785069687391`，与旧用户消息相差 6,161,388ms，正好是截图中的 `102分41秒`。最新官方用户到 1.4.486 最终正文实际约 477,709ms，即约 `7分58秒`。

## 根因

1. canonical 全量历史被单调性门禁正确拒绝后，加法恢复只认识“同一最新用户轮”；当本地连最新用户边界都漏掉时，完整官方尾轮无法落盘。
2. 完成态正文选择把“事件数组最后一段”误当成“时间上最后生成的正文”。迟到 snapshot/reconciliation 会破坏该假设。
3. 轮次耗时把状态采样、用量回填和恢复状态当成 Agent 工作过程。缺失边界后的状态还会被归到上一轮并无限延长其耗时。

## 最小安全修复

- 不重排事件数组，不修改 WS、draft、offset、完成屏障或实时刷新逻辑。
- whole-history 仍保持保守拒绝；仅当 canonical 最新用户时间严格晚于本地最新用户、该用户在本地完全不存在，且其后有非空可见最终正文时，恢复该新轮。
- v2.20.29 曾只追加“用户边界 + 最终 Assistant”，导致正文与耗时恢复、但新轮没有可展开思考/工具。v2.20.30 改为轮次原子恢复：本地只有 status 等被动残片时追加完整 canonical 新轮尾部；本地已有可见过程时，把残片重锚到新用户之后并只补最终正文，避免薄 canonical 覆盖丰富本地过程。已形成的 body-only 尾轮会在 canonical 提供过程历史时自动升级。
- reconciliation circuit key 从 v3 经 v4 升为 v5，使旧拒绝指纹不会阻止升级后的单次恢复。
- 完成态从 text blocks 中选择最大有效事件 timestamp 的文本块；timestamp 相同仍取数组中靠后的块，保留官方同时间事件顺序。
- 派生轮次结束时间只统计 Assistant、工具、子代理、审批/提问、错误等实际过程事件；排除 status、usage、change summary 等可能迟到的投影事件。
- 增加回归测试，覆盖“严格更新用户边界 + 最终正文恢复及幂等”“不同/较旧用户拒绝”“较早稳定快照迟到追加”和“终态后状态采样不延长耗时”。
