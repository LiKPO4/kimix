# 完成回放与上游短句断行：事件快照

## 现场

- 首次短句截图版本：`v2.21.19`；最新复验版本：`v2.21.21`。
- Server 会话：`session_8a50c19b-43b5-4669-83e7-709866228f79`
- 多 part 样本：`msg_session_8a50c19b-43b5-4669-83e7-709866228f79_000013`、`..._000022`
- 最新单 part 样本：`msg_session_8a50c19b-43b5-4669-83e7-709866228f79_000024`

## 证据

官方 Kimi Code 的拼接语义是原样追加：流式 transcript 使用 `open.text += delta`，相邻 text part 的默认抽取使用 `join('')`。Kimix v2.21.18 的完成回放也逐 part 原样发送，没有人为分隔符。

多 part 正常样本 `..._000013` 在空分隔连接时为 128 字、15 个换行；人为在 part 之间插入 `\n` 会膨胀为 157 字、44 个换行。`..._000022` 同样会从 114 字、34 个换行膨胀为 134 字、54 个换行。这证明 v2.21.20 前的临时 `join("\n")` 会制造额外断行。

最新异常样本 `..._000024` 不同：官方 `/messages` 只有一个 text part，原文已经是 136 字、45 个换行；空分隔与换行分隔结果完全相同。主进程诊断日志中的 `assistant.delta` offset 连续到 136，UI 最终投影也是 136 字。因此这一次短句格式在进入 Kimix 完成回放和 Renderer 之前已经存在，Kimix 没有增加、删除或重排字符。当前证据能定位到供应商/模型响应或其上游适配层，尚不能在没有原始 Provider SSE 的情况下进一步区分两者。

## 原始 SSE 对照

使用同一 `opencode-go/deepseek-v4-flash`、`reasoning_effort=xhigh` 做了一次受控直连，要求标题、四句诗和解释段按正常中文排版：

- Provider 返回 HTTP 200 / SSE，共 150 个事件、105 个正文 chunk、43 个思考 chunk。
- 正文 chunk 大多只有 1–3 个字，但只有模型明确输出段落边界的 chunk 携带换行。
- 按官方 `+=` 规则拼接后为 130 字、5 个换行、2 组空行，排版正常。

同一提示词再走官方 Kimi Code Server：最终落库为 1 个 text part、266 字、9 个换行、3 组空行，标题、四句诗和解释段同样正常。诊断会话随后归档。SDK OpenAI 适配器逐个 yield `delta.content`，相邻文本由 `mergeInPlace` 执行 `target.text += source.text`，所以不存在把网络 chunk 自动转换成段落的系统路径。

原问题会话的时间序列则显示上下文放大：切换到该线路后的第一条异常回复已经是单 part 的 236 字/90 换行；后续用户连续发送“写一个简单的俳句”“再写一个”“再来一个”“五言”等依赖上文的短指令，模型依次返回 177/63、113/36、114/34、136/45（字符/换行）。第一条异常输出进入上下文后，后续省略指令持续模仿其格式。受控对照证明这不是所有请求都会触发的 SDK/Renderer 拼接缺陷；对原始异常轮，因当时未保存 Provider SSE，仍只能归因到该轮模型/线路输出，不能在模型与网关之间继续细分。

## 根因

这里有两个独立根因：

1. 短暂双正文来自 live 草稿与同一稳定消息的完成回放被当成两份正文追加；正确修复是按稳定身份原子替换，不是改写正文。
2. v2.21.20 前的额外 `join("\n")` 会放大多 part 消息的断行；v2.21.21 已恢复官方空分隔语义。最新单 part 异常则是上游原文，不能通过 Renderer 拼接修复。
3. 原会话的后续短指令会继承已异常的回答格式，形成上下文放大；新会话或显式完整格式要求可切断这种模仿，但不应由 Renderer 擅自改写历史正文。

## 修复不变量

- 普通流式 delta 必须按 offset 原样连续追加；不得按 chunk/part 边界补空格或换行。
- 完成回放可以为原子替换聚合成一个权威正文，但必须使用空分隔连接 text part，保持逐字节等价。
- 去重只依赖 session/turn/稳定消息身份和 full-body 语义，不得依赖正文格式化、空白折叠或“短句修复”。
- 单 part 上游正文即使换行异常也必须原样显示；自动折叠空白会破坏诗歌、Markdown 和代码，不能作为通用兜底。
