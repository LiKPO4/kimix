# v2.21.20 完成回放短句断行：事件快照

## 现场

- UI 显示版本：`v2.21.19`（截图版本落后于当前源码；问题对应的完成回放实现相同）。
- Server 会话：`session_8a50c19b-43b5-4669-83e7-709866228f79`
- 典型官方消息：`msg_session_8a50c19b-43b5-4669-83e7-709866228f79_000022`

## 证据

`/messages` 返回的 Assistant 正文是多个 text part。每个 part 已经包含协议原始空格和换行，例如标题、句子和段落边界；这些不是 UI 生成的换行。相邻 part 直接连接才是官方正文，当前消息的 text part 连接后为 114 字。

## 根因

完成屏障整文聚合为了修复重复正文，曾把 text part 用 `join("\\n")` 连接。该分隔符并不属于协议正文，相当于在每个 part 之间额外插入换行；短 part（如标题、五言句、七言句）因此被渲染成一行一条，看起来像输出断断续续。

## 修复不变量

完成回放必须重建落库正文的原始文本：只连接 text part，不添加任何分隔符；part 自身携带的换行原样保留。普通流式 delta 和非文本 part 不受影响。
