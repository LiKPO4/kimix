# Kimix v2.20.1

本版本从 v2.19.5 起算，是一次大规模根治版本，聚焦启动卡顿、历史轮次正文消失、消息拼接错乱与事件顺序错乱四个问题。

## 启动性能

- **增量持久化**：会话数据改为按会话分键存储，每次自动保存仅写入发生过变化的会话。365 个会话 / 39560 事件的场景下，单次保存耗时从 1.4-13.9 秒降至接近 0ms（无变化时完全跳过）。
- **reconcile 熔断**：修复循环/启动恢复遇到官方历史被本地保护逻辑拒绝（如缺工具帧）时，不再每秒重试 15 次，改为仅当官方历史实际增长后才重试一次。
- **订阅收口**：避免 setState 假变化（如 `map()` 产出新数组但元素未变）触发不必要的自动保存；启动窗口内的归档/删除操作合并到防抖队列。

## 历史轮次修复

- **正文消失根治**：`mergeEvents` 在工具事件之后到达的正文 delta 不再合并到工具之前的助理事件，而是作为新助理事件追加，确保 turnBlocks 能正确渲染（最终答案段在工具之后、底部可见正文）。已在 v2.20.0 6018d6e 做显示兜底，本次 69b2581 完成治本。
- **正文乱序修复**：正文 delta 按 `streamOffset` 排序拼接，根治 grok-4.5 等第三方 provider 的 delta 乱序到达导致的"你好"拼成"霖江路…你好"格式错乱。
- **事件顺序修复**：`completionBarrierReplay` 绑定保留 placeholder 早期时间戳，导致同轮官方消息顺序错乱（预告在汇总之后）。已修 barrier 绑定取官方 timestamp，并追加 hydration 重排修复存量数据。
- **排除空帧噪音**：已完成轮次后多余的 step.end/turn.ended 空完成帧不再追加到事件数组。

## 其他

- rejected/accepted 日志新增 `callerReason` 字段，可区分 repair / startup / running-sample 调用来源。
- persist.run 日志新增 `changedSessions` / `totalSessions` 字段，可直接观测增量命中率。

## 已知边界

- 旧单键格式 `kimix_sessions` 会在首次增量保存后自动迁移并删除，若首次写入失败则保留旧键，下次重试继续迁移。
- 熔断指纹存储在 localStorage，最大 500 条；超过时自动淘汰最早记录。
- 跨步工具边界断段后，编辑历史事件（change_summary/todo）等尾部事件的来源可能与原步不同；这是官方分步设计的预期行为，不视为缺陷。
