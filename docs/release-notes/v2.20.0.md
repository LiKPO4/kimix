# Kimix v2.20.0

本版本专注于根治启动卡顿，从三个层面消除启动后 30 秒窗口内的主线程长任务密集问题。

## 启动性能

- **增量持久化**：会话数据改为按会话分键存储，每次自动保存仅写入发生过变化的会话（启动后首次保存跳过全部会话，因为数据刚从磁盘读出未变）。365 个会话 / 39560 事件的场景下，单次保存耗时从 1.4-13.9 秒降至约 <50ms（无变化时完全跳过）。
- **reconcile 熔断**：修复循环/启动恢复/运行中快照采样在遇到官方历史被本地保护逻辑拒绝（如缺工具帧）时，不再每秒重试 15 次，改为仅当官方历史实际增长后才重试一次。同指纹的拒绝单一目标最多执行一次。
- **订阅收口**：避免 setState 假变化（如 `map()` 产出新数组但元素未变）触发不必要的自动保存；启动窗口内的归档/删除操作合并到防抖队列而非立即写入磁盘。

## 可观测性

- rejected/accepted 日志新增 `callerReason` 字段，可区分 repair / startup / running-sample 调用来源。
- persist.run 日志新增 `changedSessions` / `totalSessions` 字段，可直接观测增量命中率。

## 已知边界

- 旧单键格式 `kimix_sessions` 会在首次增量保存后自动迁移并删除，若首次写入失败则保留旧键，下次重试继续迁移。该回退路径确保数据不丢失。
- 熔断指纹存储在 localStorage，最大 500 条；超过时自动淘汰最早记录。若 canoncial 数据在两次启动间发生变化，指纹变化后熔断自动解除，触发一次完整重试。
